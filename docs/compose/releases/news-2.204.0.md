# 2.204.0

> 本次主题：**老包升级质量**。1.9–1.12 的旧包升级到 1.13+ 时，包里未修改的旧原版模型 /
> 方块状态会让位给目标版本自己的资源；另外新增转换期纹理自检、ZIP / 文件夹两种产物形态，
> 并完成仓库迁移到 `2-Pyramid-Studio`。本版是普通 `Stable-` 更新，**不是强制更新**。

## 主要变化

### 旧原版模型自动让位

1.9–1.12（`pack_format` 2 / 3）的旧包，常常把当时整套原版 `models/` 与 `blockstates/`
一起打进包里。升级到 1.13+ 后，这些旧 JSON 仍然留在包内，会覆盖目标版本已经重定义的模型与
方块状态 —— 典型症状是**紫黑方块、方块几何错乱、手持物品大小/角度异常**；作者明明只改了贴图，
却要为这些旧文件买单。

本版新增 `drop_unmodified_legacy_models`：转换时对每个 `models/**.json`、`blockstates/**.json`
计算**规范化 JSON 的 SHA-256**，与官方客户端 jar 生成的旧版指纹比对。

- 命中指纹 = 这个文件**没被作者改过**：如果目标版本官方还有同一路径，就让位（从产物中停用），
  目标版本加载自己的资源；
- 如果目标版本官方**没有**这个路径，保留旧文件并记录说明 —— 直接删会让引用它的自定义内容失去模型；
- 作者改过的文件、解析失败的文件、非 JSON 文件一律不碰。

实测（真实 1.12.2 原版 `cube_all` / `blockstates/stone` + 作者改过与自定义模型，3→34）：
`scanned=5 / removed=2 / target_missing_kept=1`，两个原版文件消失，作者改过与自定义文件字节不变。

**边界**：只覆盖来源 `pack_format` 2/3 → 目标 ≥4；`format 1`（1.6–1.8）沿用原有处理路径。
识别数据覆盖当前 23 个 Java 目标档位；将来新增目标格式需要重新生成参考数据（见下）。

### 转换期纹理自检

两类常见坏图现在会在转换时自动修复，不需要用户逐张检查：

- **JPEG 伪装成 PNG**：内容是 JPEG（magic `FF D8 FF`）却命名为 `.png` 的贴图，会被解码并
  重编码为真 PNG；正常 PNG 逐字节不动。真实包实测扫描 1068 张、0 张误改。
- **旧包假透明背景**：1.6–1.8 旧工具常用 alpha=1–2 的矩形当“透明背景”，转到 1.9+ 后渲染器会
  沿这个矩形挤出物品侧面（物品看起来像厚方块）。现在会清理大面积、触边、含 alpha 1/2 的连通区域，
  阈值保守（触边 + 面积 ≥max(64px, 5%)），手绘的半透明边缘不会被误删。

转换页的「图层修复」开关也从“空开关”变成真实实现：恢复历史 9 条像素规则，默认关，开启时才改写
PNG 像素。关闭时产物逐字节不变。

**注意**：假透明清理依据包**自称**的 `pack_format` 触发。只是把 `pack_format` 填错、内容其实是
新版的包，转换前建议先把版本号改对，否则少量 alpha 1–2 边缘可能被清成透明。

### 输出形态：ZIP 或文件夹

- 转换产物可选 **ZIP 压缩包** 或 **解压文件夹**（设置 → 输出形态；CLI `--folder`）。目录名沿用
  输出命名模板（= 同名 zip 去掉扩展名），`pack.mcmeta` 与 `2pyr-gen.json` 一并保留。
- 文件夹模式**不覆盖已有目录**：同名目录已存在时直接报错，避免把用户自己的文件夹当产物清空。
  Bedrock 目标（`.mcpack`）不支持文件夹输出，会明确报错而不是静默改回 ZIP。
- ZIP 输出使用最高 DEFLATE 级别：同内容实测 260,500 B 语料 41,311 → 39,730 B（−3.83%）。
  压缩字节因此与旧版本不同（条目内容逐条一致），`--pack-diff --strict` 会如实报压缩差异。
- CLI 新增 `--versions`：列出全部目标标签与 `pack_format`，方便脚本枚举 `--to` 取值。

### 仓库迁移到 `2-Pyramid-Studio`

仓库地址迁移为 **<https://github.com/2-Pyramid-Studio/2-Pyramid>**。更新器 API、安装器、
README、legal 与 MSI 帮助链接已全部指向新组织。

- 新版本会直接查询新组织；
- 尚未更新的旧客户端仍可通过 GitHub 的 transfer redirect 看到并下载新版本（实测旧 API 返回 200，
  返回的资产 URL 已指向新组织），因此本版**不需要** `Safe-` 强制更新。

### 参考数据与合规

旧版模型识别依赖两张从 **官方客户端 jar** 重新生成的参考表：

- `legacy-defaults.json`（1.03 MB）：legacy[2] 1486 models + 360 blockstates、
  legacy[3] 1597 models + 408 blockstates、23 个目标档位的 `target_missing`；
- 11 条完全 synthetic 的 Python↔Rust canonicalization 夹具。

仓库只提交**路径**与**规范化 JSON 的 SHA-256**（以及来源 jar 的版本 / SHA-256 / 字节数元信息），
**不含任何官方纹理、模型、音效或其它资源文件**；生成器下载的 jar 只作为本机构建期缓存
（`tools/.mc-cache/`，已 gitignore），不随源码、安装包或转换产物分发。第三方声明（中英）已同步更新。

## 验证

- `cargo test --lib`：365 passed / 0 failed / 6 ignored；
- 真实 1.12.2 原版模型 + 自定义模型 smoke：3→34 / 3→46 / 3→97 行为一致，自定义内容字节不变；
- 未命中版本矩阵的转换（如 15→34）计划与产物保持原样；
- 文件夹输出与 ZIP 条目集合一致（除 `2pyr-gen.json` 时间戳），已存在目录 / Bedrock + folder /
  输出路径指向源包等边界均按契约报错。

## 已知边界

- 旧原版模型停用只覆盖 1.9–1.12 → 1.13+；新增目标格式需重新运行 `tools/gen-mc-reference.py`。
- 文件夹输出不覆盖已有目录；重复转换请先改名或换输出目录。
- ZIP 压缩字节不再可作为稳定指纹，`--pack-diff --strict` 会报 `COMPRESSED-BYTES-DIFF`。
