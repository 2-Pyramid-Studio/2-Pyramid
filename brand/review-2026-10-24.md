## 1. 结论

**方向可采纳**：Precision Geometry（精密几何）与现有识别资产、项目 UI 规范（单色、无渐变、克制）一致；
提案本质上是**现有三角形标识的演进 / 规整**，不是换品牌。但资产本身有 3 个技术缺口、仓库落地有明确依赖点，
必须先解决再替换发行图标。

## 2. 提案主张的实测核验（全部成立）

| 提案主张 | 实测 |
|---|---|
| 当前原稿 680×680、图形只占画布一部分 | 成立：旧 `2pyr-logo.svg` 680×680，墨迹 **45.1%×49.8%**（x 28.9%–74.2%） |

新的横向组合（960×240，含转曲文字）实测墨迹 bbox x 41–585 / y 41–196。

## 3. 资产本身的技术缺口

1. **mark（512 画布）不适合小尺寸**：stroke 12 → 32px 时 0.75px，仍是亚像素；必须组合使用
   mark（大尺寸）/ favicon（≤48）。favicon 画布 430 视口、stroke 20/16，在 16px 也仅 ≈0.74px，
   16/24 建议再做一档手工微调版（已落地为 **micro**：stroke 30/24）。
2. **横向组合**：live text 未转曲；且只有黑色版，缺深色背景用的白色版。**Stage 1 已解决**：转曲为 path
   （WPF `GlyphTypeface` 轮廓，Arial Bold / Regular），并新增白色版。
3. **没有「应用图标底板」方案**：提案资产全是透明底单色。旧 exe 图标是**白色不透明方板 + 黑色细线**
   （`c215da8` 有意保留白底：深色任务栏上黑线不可见；实测透明黑标在 `#202020` 上几乎消失）。
   落地必须决定底板形态——推荐**白底圆角方板 + 加粗 favicon（16–48）/ 细 mark（64+）**。

## 4. 仓库落地依赖（改图标会牵动的地方）

- 旧源 `2pyr-logo.svg`（gitignored，680 画布）→ `tools/generate-logos.mjs`（sharp）→
  `public/favicon*.png`、`src/assets/logo-{256,512}.png`、`logo-source.png`（喂 `tauri icon`）。
  **Stage 1 已改为从 `brand/` 的 SVG 生成**，旧 `2pyr-logo.svg` 不再参与，`logo-source.png` 输出移除。
- `public/` 另有 `logo-mark.png`、`logo-transparent.png`、`logo-white.png` 三个**不由脚本生成**的变体
  → 手工维护会漂移；`index.html` 的开屏用 `/logo-mark.png`，`App.vue` 的 FLIP 飞行要求它与
  `src/assets/logo-512.png` 同图。**Stage 1 已全部纳入 `tools/generate-logos.mjs` 输出契约**，
  其中 `logo-white.png` 旧文件是白底不透明，已修正为白色线条 + 透明底。
- 应用内度量写死旧墨迹比例：`HomePage.vue` 注释 / 负 margin（旧 45%×50% → 新 mark 71.5%×71.5%，
  64px 盒内可见尺寸会从 ~30px 变 ~46px，必须重算）；`StartupPage.vue` 内联 SVG 复制了旧几何
  （680 viewBox + non-scaling-stroke）；`VersionInfoDialog.vue` 用 `/favicon-192.png`（新代码已引用
  新增的 `/logo-192.png`）。Stage 2 处理。
- OS 图标：`src-tauri/icons/*`（ICO 六档 + MSIX Square*/StoreLogo/Wide/Splash）此前由 `tauri icon` 从
  `logo-source.png` 生成；`tools/build_release.py` 直接把 `src-tauri/icons/{StoreLogo,Square*,Wide,Splash}`
  拷进 MSIX。实测 `Wide310x150Logo.png` 与 `SplashScreen.png` 曾停留在 `c215da8` 之前的旧稿
  （未裁剪细线，44% 墨迹）——MSIX 里这两个资产曾过期。Stage 2 由 `tools/generate-icons.mjs` 统一重生成。
- 安装器：`installer-app/src-tauri/icons/icon.ico` 是另一份独立图标，构建脚本不重生成，必须单独更新（Stage 2）。
- README 此前只引用黑色 `logo-256.png`；GitHub 深色主题下黑标不可见。**Stage 1 已改 `<picture>`** 亮/暗两版。
- MSIX 瓦片有安全边距规则：不能直接把 87% 满墨迹的 favicon 塞进 Square310x310 等资产，需要按瓦片
  尺寸单独留白（Stage 2 的 `generate-icons.mjs` 负责）。

## 5. 落地顺序（与提案 page 5 一致）

1. **Stage 1（小步、可回滚，不动发行图标）**：`brand/` 入库提案资产 + 评审结论；README 用 `<picture>`
   亮/暗 logo；统一 `tools/generate-logos.mjs` 的源与输出清单（含白/暗变体），生成可复现的 PNG；
   横向组合转曲。**已完成（2026-10-24）**。
2. **Stage 2（应用图标链）**：白底圆角板 + 尺寸分档 artwork（16–48 favicon 微调、64+ mark）；
   由 `tools/generate-icons.mjs` 重生成 `src-tauri/icons/*`（含 MSIX Wide/Splash）与 installer 图标；
   同步 `HomePage.vue` / `StartupPage.vue` / `VersionInfoDialog.vue` 的度量与内联 SVG。
3. **Stage 3（验证与提交）**：16/24/32/48/128/256 浅深底实测 + Windows 任务栏/标题栏/安装器/MSIX
   实机截图；构建三项全绿；分 2–3 个独立 commit；不随版本号发布，发版前再定。

## 6. 维护者裁定（2026-10-24）

1. **采用 Precision Geometry 方向**（现有标识的演进，不换品牌）。
2. **OS 图标采用白底圆角方板 + 尺寸分档 artwork**：16–48 用加粗 favicon 版，64+ 用细 mark 版；
   由 `tools/generate-icons.mjs` 生成，不手改 `.ico` / MSIX 资产。
3. **mark / favicon / micro 三档分开使用**：micro 仅 16–24px，favicon ≤48px，mark ≥64px；
   `mark` 用于大尺寸展示，`white` 变体用于深色背景，`horizontal` 用于文档 / 横版材料。
4. 内线终点与外面留 ~34/512 的间隙**作为方向接受**（不再回到“与外边相接”）。
5. 横向组合描述语沿用提案 `RESOURCE PACK CONVERTER`；文字转曲后不再依赖字体。
   若维护者以后更换描述语，需要重新转曲（见 [README.md](./README.md) 的“横向组合”一节）。

- 16px 下 micro 版的实机可辨认度需在 Stage 3 做浅/深底截图复核（本次仅像素与渲染目检）。
- 应用内 `HomePage.vue` 的负 margin 等旧墨迹比例假设在 Stage 2 前仍可能造成视觉偏移。
